Site design — the unified Recycling Empire site (Phase 6)

This document is the UI/UX contract for the static site that tools/site-builder/build.py renders from materials/ into docs/. It is system-level (shared by every material) and follows the PLAYBOOK rules: plain markdown stays the source of truth; the builder only presents it.

1. Design goals

  1. Read first. The content is long-form, citation-heavy research. The UI exists to make a non-expert (the team, a reviewer, a funder) finish reading a method page — calm colors, one readable measure, no visual noise.

  2. Trust through labeling. The four evidence labels are the project's identity. They get a permanent color system, a legend in the footer, and the claim text itself carries the label color as a highlight (hover/focus shows the canonical charter definition).

  3. The stop-condition is never hidden. The metals gate (Cd/Pb/As/Hg) banner appears on the home page, every material dashboard, and the ranking page. It is part of the design, not a footnote.

  4. Zero-JavaScript-by-default. The only JS is the search overlay, the tooltip bubble, the wide-table column pinning, and the table-of-contents highlight; every page works without it (labels, citations and code tooltips degrade to visible chips / title attributes). No frameworks, no build dependencies beyond Python markdown + PyYAML.

  5. No monospace anywhere. The user's explicit rule: mono fonts read as "developer tool", not research. Code spans, IDs, temperatures and numbers are set in Inter (tabular figures where alignment matters).

2. Typography

Role Font Notes
Display + headings (H1/H2, card titles, hero) Fraunces (Google Fonts, variable, opsz 9-144) Serif with warm, editorial character; pairs naturally with Inter; gives the knowledge base a "publication" voice
Body, UI, navigation, tables, chips Inter (Google Fonts, 400/500/600/700) The workhorse; font-feature-settings: "cv11" for a readable lowercase l; "tnum" (tabular numerals) on tables and metadata
Everything else (code, IDs, timestamps) Inter — mono is banned Code spans get a subtle paper-shade background instead of a font change
  • Load: one display=swap stylesheet, weights 400/500/600/700 only (fast).

  • Fallbacks: Inter, system-ui, -apple-system, "Segoe UI", sans-serif and "Fraunces", Georgia, "Times New Roman", serif.

  • Scale: H1 clamp(1.9rem→2.4rem) in Fraunces 600; H2 1.35rem Fraunces 600; body 1rem/1.7; long-form measure max 68ch; table text 0.85-0.9rem.

3. The writing system (readability contract)

The prose framework every page follows, so a reader with no or moderate domain expertise can scan a page before committing to reading it. It is plain-language writing with BLUF ("bottom line up front"), applied to research pages:

  1. Answer first. Every section opens with its conclusion — a bolded lead ("The route in one paragraph. …") or a short lede. Background never comes before the answer.

  2. One idea per paragraph. At most ~3 sentences; a paragraph carrying two ideas is split, and a paragraph longer than ~5 sentences becomes a list or a table.

  3. Parallel facts become bullet lists, each bullet opened by a bold lead-in ("Tar/PAH/semi-polars — polarity-graded extraction. …"); sequences become numbered lists; comparisons become tables (e.g. INV-01 § 1: registry entries vs. what the invention does instead).

  4. Claim, then evidence, in the same block. The first sentence carries the claim; the numbers, source anchors and caveats follow immediately — never a paragraph later.

  5. Labels ride with the claim they qualify. An evidence tag sits directly after the sentence it grades; the builder turns the tag word into a background highlight ON the claim text itself (label color = tag color; hover/focus shows the canonical charter definition), so the floating label word disappears and the colored sentence carries the meaning. Never clustered at the end of a paragraph.

  6. Units and anchors every time. Every number carries its unit and its source anchor ("35.4 g/L measured in dark liquor (M-03)").

  7. One concept, one name. Terms are used consistently and point to the glossary on first use; synonyms are avoided.

  8. Falsifiers are explicit. Where a claim could be killed, the page names the test that would kill it.

The builder enforces the structural half mechanically: lists that directly follow a paragraph line are re-spaced so they render as lists (normalize_lists), generated tables get the data-table style with bare-number cells centered (enhance_tables), evidence tags become sentence-level highlights (wrap_evidence), [S# p.x] citations become clickable superscripts with the source title in a tooltip (cite_superscripts + citation_map), internal codes (M-xx / INV-xx / C-xx / P-x, INV-01 streams S1-S5) become dotted-underline links with explanatory tooltips (annotate_codes), and long measures stay capped at 68ch.

6. Navigation model (easy navigation)

Three persistent layers + one overlay:

  1. Top bar (sticky, every page): wordmark "Recycling Empire" → home; links Materials, Charter & Playbook, About; search button (Ctrl/⌘-K, also plain /).

  2. Material sidebar (left, sticky on all materials/<slug>/ pages, collapsed to a horizontal chip-row under the top bar on mobile): Overview · Ranking · Methods (8) · Registry · Invention · Reports · Sources (81) · Research · Charter · Glossary · State & log — the full map is always one click away.

  3. "On this page" (right rail on wide screens, only on long pages): H2-level TOC from the markdown, with scroll-spy highlighting; collapses under the content on narrow screens.

  4. Search overlay: client-side, index prebuilt at generation time (search-index.json, page titles + headings + text, sources included). Scores title > heading > body; results grouped by section; Esc closes; fully keyboard-navigable.

Every page also carries: breadcrumbs (Home › Cigarette butts › Methods › M-01), and prev/next pagers inside sequential groups (methods in registry order, sources alphabetical).

7. The reading journey (designed path)

The material dashboard is the journey's hub. Its "Start here" block prescribes one order:

  1. Overview (dashboard) — what this material is, its version, phase, stop-condition.

  2. Ranking — the verdict: Table A top routes, why M-08 leads (the only published metals-gate pass), the test-first list. If you read one page, read this.

  3. Final reports — the evidence boundary in full prose (batch-01 synthesis; validation & open questions).

  4. Methods M-01…M-08 — the action plans, in ranking order, each with its status badge and gap-fill chips.

  5. INV-01 — the invented route that turns the field's missing mass balances into the deliverable; its falsifier ledger and red-team placeholder (Phase 7).

  6. Sources — the 81-document shelf, each with metadata and archive links.

  7. Charter, glossary, state & log — the rules and the record.

Each step's card states what you will learn and how long it takes ("short read", "deep read"), so the reader can enter anywhere without losing the thread.

8. Page templates

  • Home: hero (one sentence + two buttons: Browse materials, Read the playbook), material cards (name, one-line blurb, version/phase badge, counts), footer legend.

  • Material dashboard: identity card (name, version, status, site URL, priority methods), stop-condition banner, "Start here" journey cards, shelf counters (sources / methods / inventions / cards), ranking snapshot (top 3 rows of Table A), test-first preview, phase-progress strip, migration note link.

  • Method page: spec-sheet grid rendered from the fenced metadata block (id, name, family, status, version, sources), body with H2 sections + right-rail TOC, prev/next among methods, evidence labels inline (colored text + tooltip), archive links rewritten automatically.

  • Ranking page: the three tables verbatim with the data-table style (borders, zebra rows, tinted header, tabular numerals, centered score columns); the 8+-column score tables get a 960px minimum width, scroll horizontally inside a rounded frame with the identity column pinned and a guaranteed 250px note column; gates explained above the tables; test-first list as numbered cards.

  • Sources index: 81-row table (id, figures, original → archive, AI text → archive raw, detail page) with a filter box and type-filter chips, client-side only.

  • Source detail: SOURCE.md content (or, for the 49 sources without SOURCE.md, an honest auto-stub: id, figures count, links to the archive folder and text.md) + callout "Full document lives in the butt-lab archive".

  • Reports / research / charter / glossary / state / log: plain article template with TOC.

9. Components inventory

cards (material, journey, stat), evidence highlights (claim text with the label's background color + hover tooltip; bare chips only in the footer legend), code refs (dotted underline, tooltip, click-through for M-xx / INV-xx / C-xx / P-x), citation superscripts (numbered, clickable, source title + page in the tooltip), badges (status), banners (stop-condition), spec-sheet grid, data tables (bordered frame, zebra, tinted header; header row sticky while the wrapper scrolls vertically; identity columns pinned with solid backgrounds while it scrolls horizontally), callouts (archive links, caveat notes), breadcrumbs, TOC rail (fixed 210px track), pagers, search overlay, single clamped tooltip bubble, footer legend, 404 page with the material map. Layout variants picked at build time: 3-column (side + content + toc), no-toc, side-rail, single — a rail is always a fixed-width track, never a flex-sized column that can eat the content width.

10. Accessibility & responsiveness

  • WCAG AA contrast on every token pair (paper/ink 13.9:1; label and badge colors ≥ 4.5:1).

  • Keyboard: visible focus rings (2px accent offset), search fully operable, skip-to-content link; highlights, code refs and citation superscripts are tabbable and show the tooltip on focus.

  • Breakpoints: ≥1200px full three-column; 800-1200px two-column (TOC hides); <800px single column (sidebar → horizontal chips; tables scroll with sticky header + pinned identity columns; the second pinned column drops below 700px to keep room to scroll).

  • prefers-reduced-motion disables all transitions; no animation elsewhere.

  • Semantic HTML throughout (nav, main, article, aside); one H1 per page; descriptive link text (never "here").

11. Performance

Single CSS file (~15 KB), single JS file (~8 KB), fonts via Google Fonts with display=swap and system fallbacks, search index ≤ 500 KB, no framework, no images required for pages (the archive holds the figures). Every page renders instantly from the CDN.

12a. Review round 2 (2026-11-28, v0.8.2) — feedback fixes

Operator feedback after the first review round, all fixed at builder level (no research content changed): (1) wide-table pinned column showed the content behind it while scrolling horizontally — pinned cells now carry solid backgrounds and the wrapper scrolls vertically too with the header row pinned; the second (identity) column joins the pin via JS measurement below 700px viewport width it drops; (2) playbook / site-design pages: the TOC rail was auto-placed into the flex-sized column and swallowed the page — layout is now chosen per page (fixed 210px rail tracks); (3) literal ** markdown leaked into the dashboard "Test first" panel — builder snippets render inline markdown (inline_md); (4) tags: the label word is no longer shown next to the sentence — the sentence itself is highlighted in the label's color and the label lives in the tooltip (colon form what to measure (evidence: parameter not located) highlights the description); (5) [S1 p.6]-style citations became clickable superscript numbers with the source title + page in the tooltip (map built from each page's own Sources section, metadata sources: list as fallback); (6) internal codes became hoverable/clickable refs with "what this code means" tooltips; (7) root pages no longer render their title twice; (8) the CSS pseudo-element tooltip was replaced by one JS-positioned bubble clamped to the viewport (same dark style), also shown on focus and touch.

12b. Review round 3 (2026-11-28, v0.8.3) — reading pass

Second feedback round, focused on how the site reads (no research content changed): (1) the JS tooltip bubble now opens below the hovered target by default and flips above only when the viewport bottom would clip it — and the bubble's arrow sits on the side that actually points at the target (round 2 had it inverted); (2) 67 tooltips carried a doubled code ("INV-01 — INV-01 — …") — fixed site-wide; (3) dense enumerating paragraphs restructured: the ranking page's "What was scored" is a list now, and the Test-first items carry real nested Ties / Expected measurement / Decision rule bullets; (4) thirteen pages rendered their title twice — duplicates dropped, informative ones demoted to a muted .doc-sub subtitle, anchor ids preserved; (5) the Belmont capture's raw "[S21]" became a clickable superscript to the fact-sheet source; (6) the Glossary gained a "Codes on this site" quick-reference (the numbering systems: M-xx, INV-xx, C-xx, P-x, S1–S5 streams, F0–F6 families, source slugs, superscript source numbers) and every page footer now links to it via a codes chip; the stale batch-02 gap-code table is marked as archive numbering; (7) the four arena transcripts' one unrendered "" marker fixed (code-block asterisks stay verbatim); (8) the home page title no longer doubles the brand.

12. Build & deploy

python3 tools/site-builder/build.py        # renders materials/ → docs/ (deterministic; safe to re-run)

  • GitHub Pages (chosen default): Settings → Pages → Source: Deploy from a branch, branch main, folder /docs. Site: https://abdo2048.github.io/recycling-empire/.

  • Cloudflare Pages (equivalent alternative): connect the repo, build command none, output dir docs. Private access later: Cloudflare Access in front of the domain (PLAYBOOK Phase 6).

  • After the build, commit both materials/ (source of truth) and docs/ (rendered output); MATERIALS.md and the material's material.yaml hold the live URL.
