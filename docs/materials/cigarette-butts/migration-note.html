What stayed in butt-lab (the frozen archive)

The heavy shelf cannot travel through the API-based migration path (per-file push limit ~1 MB; the archive is 546 MB). It stays in butt-lab, which is now a read-only archive:

  • sources/<id>/document.pdf / document.html — the originals (humans read these)
  • sources/<id>/text.md — the AI-readable conversions (4.7 MB)
  • sources/<id>/figures/ — extracted images
  • methods/research/2026-11-25-arena/attempts/ + cdx/ — raw fetch artifacts behind the FINDINGS
  • publication/ — the old reader's data layer (superseded by the unified site)
  • all historical dirs (archive/, docs/, state/, tools/, mcp/, operator/, …)

Every migrated file and every generated site page resolves links into the archive: originals link to https://github.com/abdo2048/butt-lab/tree/main/<path> and AI-readable text links to https://raw.githubusercontent.com/abdo2048/butt-lab/main/<path>. The builder does this rewrite automatically (see tools/site-builder/build.py).

Why this split is safe

  • The record of knowledge (plans, rankings, registry, invention, reports, source metadata) is complete here and self-contained — nothing on the site needs the binaries to be understood.

  • The originals are immutable published documents; a frozen public archive repo is a stable link target, and each document also exists in a second copy under the operator's control (butt-materials / local machine).

  • If a full byte-level move is ever wanted, a single local operation completes it: git clone https://github.com/abdo2048/butt-lab && cp -r butt-lab/sources/* recycling-empire/materials/cigarette-butts/sources/ — the builder already handles both layouts (it links locally when a file exists in the folder).

Reader retirement

The old reader at https://butt-lab.am6.workers.dev/ (Cloudflare Worker over publication/) is superseded by the unified site. Decommissioning the Worker is an operator step: it serves a frozen snapshot and stays up until the operator switches it off. MATERIALS.md records the change.
